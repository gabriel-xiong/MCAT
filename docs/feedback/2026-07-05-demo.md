## 1. Prefer binary classifications over extra layers

**Feedback (verbatim):** More binary classifications (e.g. “did you find this
hard?” yes/no) instead of the extra layers we have now.

### Current state

**BrainLift error taxonomy (science):** On a performance miss the engine infers
one of three buckets — `content_gap`, `application`, `misread` — documented in
[`docs/BRAINLIFT.md`](../BRAINLIFT.md) and [`docs/ERROR-DIAGNOSIS-SPEC.md`](../ERROR-DIAGNOSIS-SPEC.md). Legacy four-button labels (`reasoning`,
`passage_mapping`) fold to `application` in dashboard focus routing
(`anki-MCAT/pylib/anki/mcat_scores.py`).

**Multi-step miss UX (science, `performance_dialog.py`):**

1. Select answer → **Confirm**
2. On miss: optional **immediate content re-check probe** (blanked recall → Show
   answer → self-grade PASS/FAIL) *before* explanation is revealed
3. **Classification confirm** — scaffolded hypothesis (“looks like *X* — right?”)
   plus three override buttons for the v2 buckets
4. Then explanation, `choice_feedback`, and remediation slot

**Inference signals (not binary):** `infer_error_type()` combines
`cognitive_demand`, FSRS-R of backing cards (`M`), authored
`choice_diagnosis` tags (71× `content_gap`, 12× trap, 7× null in the bank),
timing/trap heuristics, and probe outcome (`recheck_correct`). Confidence is
continuous, not yes/no.

**“Not sure” / IDK:** Secondary **Not sure** button (non-CARS). Maps **directly**
to `content_gap` with `error_source = idk`; row flagged `idk = 1`, excluded from
Performance accuracy and Readiness (`DECISIONS` §30; `mcat_perf.py`,
`mcat_scores.py`). No probe, no confirm step on IDK. CARS IDK → `unresolved`.
Deferred richer IDK (confidence weighting, probe-resolved IDK) tracked in
[`docs/LOOSE-ENDS.md`](../LOOSE-ENDS.md).

**CARS:** Error-type confirm omitted on miss; objective skill-archetype + pacing
only (`ERROR-DIAGNOSIS-SPEC.md` → “CARS diagnosis”).

**What is “extra layers” today:** probe → inferred 3-bucket label → confirm/
override → error-type-specific remediation channel — vs a single binary prompt
per step.

### Proposed direction

- Add **low-friction binary checkpoints** at decision points (e.g. “Was this
  hard?” yes/no; “Did you know the fact but misapply it?” yes/no) that *feed*
  the existing buckets rather than asking students to pick taxonomy labels.
- Treat binary answers as **features** in `feature_json` / inference rules first;
  keep the three dashboard buckets for next-action routing unless eval shows a
  simpler surface is enough.
- Revisit whether the **confirm + three override buttons** should collapse to
  one binary (“Agree with diagnosis?”) plus override menu for power users.
- Preserve IDK honesty rules: any new binary signal must not leak into Readiness
  without explicit gating (same bar as IDK today).

### Priority

**Post-Sunday** — requires UX simplification pass + eval of whether binary
signals improve routing vs the current probe + inference stack.

**Cross-refs:** `docs/ERROR-DIAGNOSIS-SPEC.md`, `docs/LOOSE-ENDS.md` (self-diagnosis
research, CARS confirm gap, probe-confirmed IDK), `anki-MCAT/qt/aqt/mcat/performance_dialog.py`,
`anki-MCAT/pylib/anki/mcat_perf.py` (`infer_error_type`, `not_sure()`).

## 2. Substantiate research more

**Feedback (verbatim):** Substantiate research more.

### Current state (what exists vs what is thin)

| Where research should live | What is there today | Gap |
|----------------------------|---------------------|-----|
| [`docs/PRD.md`](../PRD.md) | Product requirements, scoring rules | Few primary citations; claims stated as product rules |
| [`docs/DECISIONS.md`](../DECISIONS.md) | Locked design choices (§9 confirm vs self-report, §21 inference rebalance, §30 IDK) | Rationale is internal; not a literature review |
| [`docs/MODELS.md`](../MODELS.md) | Memory / Performance / Readiness formulas + eval harnesses | Formulas implemented; **n=1 / SYNTHETIC** caveats prominent; FSRS calibration pending real revlog at scale |
| [`docs/BRAINLIFT.md`](../BRAINLIFT.md) | Thesis + paraphrase-gap instrument | Strong narrative; cites mechanism, not effect sizes |
| [`docs/ERROR-DIAGNOSIS-SPEC.md`](../ERROR-DIAGNOSIS-SPEC.md) | Inference design + honesty guards | **Load-bearing extrapolation:** Dunning-Kruger / calibration literature → “students can’t categorize *why* they missed” — flagged as needing support in `LOOSE-ENDS.md` |
| [`docs/LOOSE-ENDS.md`](../LOOSE-ENDS.md) | Explicit “Research” section | Open item: separate **established** (overestimate performance) from **our inference** (error-type self-classification unreliable); gold set missing |
| **Eval artifacts** (`docs/artifacts/`, `make eval-*`) | Memory calibration, paraphrase gap, held-out pool, Step 2 prediction, leakage check | Mostly **SYNTHETIC-labelled** demos; real friend held-out + think-aloud **not yet** the cited evidence (`docs/SUBMISSION-RESULTS.md`) |
| **Gold set** | Spec’d ~20–30 think-aloud items | **Does not exist** (`LOOSE-ENDS.md`) |

**Thin today:** No bibliography with effect sizes; no published-style “related work”
section; inference quality unvalidated on gold labels; small-n honesty is
documented but easy to under-read in demo.

### Proposed direction

- Add a **`docs/RESEARCH.md`** (or expand PRD appendix): primary sources for
  (a) miscalibration / overconfidence, (b) error-type or metacognitive
  self-report reliability, (c) interleaving / transfer if cited for study
  feature — each with **effect size or qualitative strength**, not BrainLift
  restatement.
- Run the **gold set** (friend think-aloud on held_out subset) and report
  inference accuracy / override rate against probe labels — feeds
  `ERROR-DIAGNOSIS-SPEC` and `w_mis` tuning.
- Replace or supplement SYNTHETIC artifact citations in submission-facing docs
  with **REAL** rows as they land (`SUBMISSION-RESULTS.md` pattern).
- Keep two claims separate in all outward copy (already named in
  `LOOSE-ENDS.md`): poor calibration of *right/wrong* vs unreliable
  *why*-diagnosis.

### Priority

**Post-Sunday** — documentation + data collection; does not block demo if
SYNTHETIC labels stay honest.

**Cross-refs:** `docs/LOOSE-ENDS.md` → Research, Gold set, Small-n honesty;
`docs/STEP2-PREDICTION.md`; `docs/PARAPHRASE-TEST.md`; `docs/SUBMISSION-RESULTS.md`.

## 3. Question difficulty scaffolding on miss

**Feedback (verbatim):** Create question difficulty scaffolding (like 1–5); when
user misses a question, route to 2 simpler lower-difficulty questions to check
content deeper.

### Current state

**Question bank schema (`data/questions.json`, `data/questions.example.json`):**
Fields include `stem`, `choices`, `correct`, `topic_id`, `section`, `skill`,
`cognitive_demand` (`recall` | `application`), `explanation`, `choice_feedback`,
`source_*`, `split`. **No `difficulty` (1–5) field** today.

**On miss — remediation by error type, not difficulty tier:**

| Inferred type | Current routing | Difficulty-aware? |
|---------------|-----------------|-------------------|
| `content_gap` | Focus → filtered memory review (flashcards in topic) | No ladder; component cards + re-check probe localize prerequisite |
| `application` | **`RemediationDialog`** — N=2 items from `data/application-practice.json` (`split: remediation`), same topic, exclude missed concept | Same difficulty band; integration pool, not “easier MCQs” |
| `misread` | Pacing / careful-reading drill message | No item routing |

**Related but not the same:** Immediate **content re-check probe** on science miss
tests one backing sub-concept objectively; **`application-practice` pool** is a
separate unscored channel (`APPLICATION-PRACTICE-POOL.md`). Neither selects
“two easier questions” from a difficulty-graded main bank.

**Step 2 eval harness** (`docs/MODELS.md` §2b) mentions “item difficulty” as a
feature for held-out prediction, but difficulty is **not authored in the bank**
— the harness uses synthetic/mock features.

### Proposed direction

- Extend **`questions.json` schema** with `difficulty` (1–5 or similar), authored
  per item with validation in `validate_data.py`.
- On miss (especially `content_gap` or ambiguous probe FAIL): inject **two
  lower-difficulty items** on the same `topic_id` / prerequisite chain before
  or instead of generic “review N cards” — distinct from the existing
  `application` remediation pool.
- Define isolation: scaffold items could live in `remediation_items` (unscored)
  or a gated “diagnostic” session mode — mirror the application-practice
  scoring firewall.
- Use probe + scaffold outcomes to **confirm** content gap vs shallow mastery
  (aligns with deferred “probe-confirmed IDK” in `LOOSE-ENDS.md`).

### Priority

**Post-Sunday** — schema change, content authoring at scale, and routing logic in
`mcat_perf.py` / `performance_dialog.py`.

**Cross-refs:** `data/questions.example.json`, `data/application-practice.json`,
`docs/APPLICATION-PRACTICE-POOL.md`, `anki-MCAT/qt/aqt/mcat/remediation_dialog.py`,
`docs/ERROR-DIAGNOSIS-SPEC.md` → content re-check probe.
